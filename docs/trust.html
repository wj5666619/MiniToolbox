TRUST CENTER / ENTERPRISE BASELINE

企业级，
是可核验的。

不卖“认证”标签，也不把单机工具说成零风险平台。这里只列已经落地的控制、能点开的证据，以及仍由企业自己承担的边界。

01
MODEL

先选部署模型。

同一个 exe，按终端管理强度分三种用法；个人用户不配置策略也不会被“企业功能”打扰。

MODEL–01

个人 / 单机

直接运行 exe。配置在程序目录或 %APPDATA%，不装服务、不写系统级驱动。

ZERO CONFIG
MODEL–02

团队 / 小规模

部署.ps1 -Install 装到当前用户，建开始菜单和卸载项；程序目录策略做轻量管控。

PER-USER
MODEL–03

受管企业

管理员写 %ProgramData%\MiniToolbox\策略.json，配合软件白名单、EDR 和网络策略。

MACHINE POLICY

策略读取顺序是机器级 → 程序级；所有策略只做收紧，程序级文件不能把机器级限制放宽。需要更强隔离时，直接禁用联网功能或整套功能页。

02
CONTROL

六个控制面。

从代码合并到终端运行，每一层都有明确机制；没有“神秘企业版开关”。

CTL–01

治理与发布

main 要求 PR、compile 状态检查、线性历史；tag 必须与源码 VER 一致。

GOVERNANCE
CTL–02

最小权限

默认当前用户运行，不自动提权；需要管理员的功能由用户显式确认，插件不伪装成已签名。

LEAST PRIVILEGE
CTL–03

策略管控

机器级 + 程序级策略；可禁用在线更新、诊断导出、指定功能页，强制详细日志。

POLICY
CTL–04

审计留痕

启动退出、清理、重装、安装/拒绝更新、导出诊断写入 日志\审计.log，控制中心可导出 CSV。

AUDIT
CTL–05

更新验签

大小 + SHA256 + 同一 Authenticode 证书指纹；未签名、异证书、哈希不符直接拒绝替换。

UPDATE CHAIN
CTL–06

数据边界

默认无账号、无云同步、无遥测；密码本/保险箱本地 AES-256 加密，诊断包按需导出。

DATA MINIMIZATION

04
SUPPLY

发布链，
不是“传个 exe”。

从源码到 Release，每一步都有产物或记录；新版本由 CI 生成来源证明，旧版本补齐校验清单。

01 / SOURCE公开源码与构建脚本，提交可追溯。
02 / CIWindows runner 编译，权限按作业最小化。
03 / SIGN可选 Authenticode；记录签名者与指纹。
04 / HASHSHA256SUMS + SBOM + update.json。
05 / RELEASEtag 与 VER 一致；来源证明随资产发布。

自签名证书只证明“同一发布链”，不等于公共 CA 信任。企业分发前应把 SHA256、签名者指纹和内部软件白名单一起核对。

05
LIMITS

不声称什么。

把边界写清楚，比堆“企业级”形容词更有用。

LIM–01

不声称认证

没有 ISO 27001、SOC 2、等保或 GDPR 认证证书；官网只用“设计对齐 / 可核验事实”。

LIM–02

不替代终端安全

不提供 EDR、DLP、网络准入、内核防护或集中身份认证；企业仍需自己的终端与网络控制。

LIM–03

不承诺合同 SLA

社区支持尽力而为；7×24、赔付、定制开发等需另行书面约定。

LIM–04

不自称零风险

本地工具仍有本地权限、第三方组件、供应链和用户误操作风险。

LIM–05

不隐藏旧版差异

Release 资产与源码维护版可能不同；下载以 Release 哈希为准，源码以 CHANGELOG 为准。

LIM–06

不做第三方背书

FFmpeg、7-Zip、WebView2、工具站等各自许可与安全责任归上游。
